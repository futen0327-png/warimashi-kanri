# 割増オペ 音声（Android オペ用アプリ・音声入力版）

既存のオペタブ（`index.html` / PWA）はそのまま使い続け、雨天・手袋作業時などの入力手段として追加する Android アプリ。
NFC タグをポケット越しにタップ → 話す → 読み上げで確認 →「送信」で、既存 Firebase の `warashi_entries` に
PWA と同じ形式で書き込む。事務所タブの改修は不要。AI API は使っていない。

## 構成

| モジュール | 内容 |
|---|---|
| `core/` | Android 非依存のロジック（JVM 単体テストあり）。発話解釈・割増の組み合わせ検証・顧客名照合・バッファ・読み上げ文言 |
| `app/` | Kotlin + Jetpack Compose。NFC（リーダーモード）、`SpeechRecognizer`、`TextToSpeech`、Firebase REST 書き込み |

主なファイル

- `core/.../UtteranceParser.kt` … 位置ベース（5-1）／項目名+値（5-2）の解釈。区切りなし（「1234こんがら2トン2割」）でも切り分ける
- `core/.../Vocabulary.kt` … 固定候補と、認識の揺れを吸収する別表記（ひらがな・同音異字など）。**実機テストで誤認識が見つかったらここに足す**
- `core/.../SurchargeRules.kt` … 割増候補ロジック（PWA の `getSurOpts` と同一）
- `core/.../VoiceInterpreter.kt` … バッファへの反映・組み合わせ検証・読み上げ文言
- `core/.../CustomerMatcher.kt` … 登録済み顧客名との編集距離照合
- `app/.../MainViewModel.kt` … タップ → 認識 → 反映 → 読み上げ → 送信 の流れ
- `app/.../AppConfig.kt` … Firebase / GAS の接続先（PWA と同じ値）

## ビルド

Android Studio で `android/` フォルダを開いて実行するか、コマンドで:

```sh
cd android
./gradlew :core:test          # ロジックの単体テスト
./gradlew :app:assembleDebug  # app/build/outputs/apk/debug/app-debug.apk
```

GitHub に push すると `.github/workflows/android.yml` がテストと APK ビルドを行い、
Actions の実行結果ページから `warimashi-voiceop-debug-apk` をダウンロードできる。

## 使い方

1. アプリを開き、マイクの使用を許可する（NFC がオフなら端末設定でオンにする）
2. 「ポケットモード」を押す（画面が最低輝度になり、タッチが無効になる。長押しで解除）
3. NFC タグをタップ → 「ピッ」の後に話す → 黙ると自動で終了し、内容が読み上げられる

| 発話例 | 動作 |
|---|---|
| 「1234、コンガラ、2トン、2割」 | ナンバー→品目→サイズ→割増 の順に入力 |
| 「パス、コンガラ、2トン、2割」 | ナンバーを空欄にして入力 |
| 「ナンバー 1234」 | 項目を指定して入力・修正（他の項目は保持） |
| 「理由 大きさ 鉄筋」／「拒否 赤レンガ」 | 複数選択（言い直すと置き換え。「理由 パス」で空欄） |
| 「客先 中川組」 | 登録済み顧客名に補正して読み上げ（登録にない名前はそのまま・「登録にない名前です」と通知） |
| 「送信」 | 必須3項目（品目・サイズ・割増）が揃っていれば送信し、バッファをクリア |
| 「取消」 | バッファを全部消す |
| 「確認」 | 今の入力内容を読み上げる |

画面のボタン（マイク／送信／取消／読み上げ）でも同じ操作ができる。

## 設計書からの補足・変更点

- **NFC はリーダーモード**（`enableReaderMode`）で読む。Foreground Dispatch と同じく前面表示中だけ有効だが、
  タグの種類を問わず受け取れ、「未対応のタグ」などのシステム表示・音が出ない。どの NFC タグでも反応する
- **画面が消えていると NFC は読めない**（Android の仕様）。そのためアプリ表示中は画面を消さず、
  ポケットモードで最低輝度＋タッチ無効にしている。電源ボタンで画面を消すと反応しなくなる点に注意
- **Firebase は REST API で書き込む**。PWA と同じく認証なしで `warashi_entries` に push する。
  Firebase SDK / `google-services.json` が不要なので、Firebase コンソールでの Android アプリ登録も不要
- **顧客名の照合のため `warashi_customers` だけは読み取る**（設計書11章「読み取りは行わない」の例外。9章で既存リストを使うため）。
  送信履歴（`warashi_entries` / `warashi_sent`）は読まない
- 送信内容は PWA の `submitEntry` と同じ: `plate, item, vehicle, surcharge, reasons(カンマ区切り), memo, customer, timestamp, confirmed:false`。
  **受入拒否品目は `memo`（旧・備考）に「、」区切り**で入れる。ナンバーは任意なので未入力なら空文字
- PWA と同じく GAS（スプレッドシート）にも記録する。不要なら `AppConfig.GAS_WEBHOOK_URL` を空にする
- PWA が行っている「新しい顧客名の自動登録」と「`warashi_sent` への履歴保存」は行わない
  （誤認識した名前が顧客リストに増えるのを避けるため／一方向送信のみの方針のため）
- 「確認」（読み上げ）コマンドを追加した（画面を見ずに今の入力内容を聞き直すため）
- 項目名+値方式で言い直した項目は**置き換え**（理由・拒否も追加ではなく置き換え）
- 品目・サイズを変えて割増が選べない組み合わせになった場合は、割増だけを外して言い直しを促す。
  石・瓦は自動で「割増なし」

## 確認済みの仕様

- 受入拒否品目は設計書3章の列挙どおり9種（赤レンガ/ラス/根っこ/木片/石/防水シート/ビニール/少ない/大きすぎる）
- ナンバーは PWA に合わせて 1〜4 桁を受け付ける
